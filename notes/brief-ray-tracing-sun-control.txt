BRIEF: Ray tracing sun control (for a Sonnet implementation thread)
Written 2026-10-22 for L. Not implemented yet. Check origin/main first (git fetch origin main, read the log for
src/gameplay/day_night.cpp, src/gameplay/hd_shadows.cpp, rt64-ext/src/render/rt64_scene_effects.cpp).

WHAT L WANTS
L picks where the main light (the sun) stands, then hands the result over as a plain txt file, and Claude turns it
into the game's defaults. So there are two halves:
  A. A live control in the game: move the sun and watch the ray traced lighting and shadows change.
  B. A txt file the control writes (and the game can also read), one line per map, which becomes the shipped
     per-map sun.

CURRENT BEHAVIOUR (verified in code 2026-10-22)
- One sun vector is sent to RT64: RT64::SetSceneSun(custom, x, y, z) in rt64-ext/src/render/rt64_scene_effects.cpp.
  It is a unit vector TOWARDS the sun in world space. y is up. Called only from src/gameplay/day_night.cpp:
    - line ~397: cycle off. Uses map_sun(map, ...) (the map_suns[] table, lines ~100-115: Spiral Mountain 0xAF and
      Jinjo Village 0x142 today) or custom=false, which falls back to FixedSun {0.47, 0.42, -0.78}.
    - line ~508: cycle on. Uses the moving "sky" vector.
- Readers of effectsSettings.sunDirection / FixedSun in rt64_scene_effects.cpp: sun shadow map (~2792, ~3303),
  snow light (~2262, needs y > 0.15), traced shadows, light beams and sky. The ray traced scene (debug view 21) and
  the traced sun shadows use the same vector, so changing the vector changes everything at once.
- tooie::day_night::sun_direction(out) returns the cycle's sun (y never below 0.18) for HD shadows tilt
  (src/gameplay/hd_shadows.cpp tilt_direction, lines ~78 and ~125-130 and ~366). It returns false when the cycle is
  off, and HD shadows then use tilt_light {0.47, 0.82, 0.33}.
- Test aid already there: TOOIE_MAP_SUN=<x>,<y>,<z> forces one sun on every map (day_night.cpp map_sun).

DESIGN (defaults chosen; L can change any of them)
1. Setting: "Sun direction" in Graphics > Ray Tracing section (group "Ray Tracing", shown before
   high_detail_models_option like the other ray tracing options in src/game/config.cpp ~842-851).
   Id: ray_tracing_sun_option. Enum: Game (default) / Custom.
     Game   = today's behaviour, nothing changes. Default must leave the picture identical.
     Custom = use the numbers below, on every map that is not driven by the Day and Night cycle.
2. Two sliders, shown only when Custom (add_option_hidden_dependency like day_night's length_option):
     ray_tracing_sun_azimuth   0 to 359 degrees, step 1, default 150. 0 = +z, 90 = +x (state the compass in the
                                description; pick one and write it in the option text).
     ray_tracing_sun_elevation 5 to 90 degrees, step 1, default 40. 90 = straight up.
   Vector: x = cos(el)*sin(az), y = sin(el), z = cos(el)*cos(az). Normalise. Clamp y >= 0.15 so the snow light
   (needs > 0.15) and shadows stay valid.
3. Live: the sliders apply as they move (project rule: settings apply live). Send through RT64::SetSceneSun each
   frame the value changes, from a small tick function; no restart. Do not reorder RasterParams or FrameParams
   (displaced ground rule). Do NOT touch lib-patches/rt64.patch; all RT64-side change stays in rt64-ext/ if any is
   needed. Ray tracing owns rt64_scene_effects.* and SceneEffectsPS.hlsl: message that thread before editing them.
   The brief needs no change there: SetSceneSun already exists.
4. HD shadows tilt: when Custom, tilt_direction (hd_shadows.cpp) should use the same vector so character shadows
   agree with the traced sun. Add tooie::sun_control::direction(out) (new small file, or put it next to
   day_night) and have both hd_shadows.cpp and day_night.cpp ask it first.
5. Priority when several sources exist (highest first):
     a. Day and Night cycle running (it moves the sun on purpose). The setting is ignored then; say so in the
        description.
     b. Custom setting.
     c. Per-map entry from the txt file (below).
     d. map_suns[] table, then FixedSun.
6. Saving the txt (this is the hand-off to Claude): a hotkey, F9 unless taken (check notes/keys.md and
   tooie::hotkeys), appends or replaces the line for the current map in sun.txt next to the config files, and
   prints "[sun] saved map 0xAF az 150 el 40" to the console. A second press of the same key is not needed.
   File format, one map per line, comments with #:
       # map(hex)  azimuth  elevation   name
       0xAF        150      40          Spiral Mountain
       0x142       262      64          Jinjo Village
   On start the game reads sun.txt if it exists; a map with a line uses that sun when the setting is Game
   (so L's file works without turning Custom on). The hand-off from L is this file: Claude then copies the lines
   into map_suns[] in day_night.cpp (converting az/el to the vector) so the default ships in code.
7. Map number: day_night.cpp already has the current map id in tick(); reuse it.
